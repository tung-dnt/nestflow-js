## OrchestratorService

The main service responsible for orchestrating workflow execution and state transitions.

### Import

```typescript
import { OrchestratorService } from 'nestflow-js/core';
```

### Methods

#### `transit(event)`

Returns a cold Observable. Each subscription runs one attempt, emits one result on success, and completes. Errors go to the subscriber. Handler retries are not scheduled, even with `@WithRetry`.

##### Signature

```typescript
transit(params: IWorkflowEvent): Observable<TransitResult>
```

Pass an [`IWorkflowEvent`](/docs/api-reference/interfaces#iworkflowevent) with a stable `eventId`. Subscribing again starts another attempt; a committed event uses its stored receipt instead of executing the handler again. Unsubscribing stops delivery to that observer, not work already started. Use `requestCancellation(event, urn)` for persisted workflow cancellation.

#### `transitAttempt`

Returns a cold Observable for one adapter attempt per subscription. Use `canRetry: true` only when another handler attempt remains.

```typescript
transitAttempt(params: IWorkflowEvent, canRetry: false): Observable<TransitResult>;
transitAttempt(
	params: IWorkflowEvent,
	canRetry: boolean,
): Observable<TransitResult | { status: 'retry' }>;
```

| Outcome | Behavior |
|---------|----------|
| Event already committed | Uses the stored receipt instead of running the handler. An `exhausted` receipt raises an exhaustion error. |
| Retryable handler error and `canRetry` is `true` | Releases the claim and returns `{ status: 'retry' }`. The adapter can schedule another attempt with the same ID. |
| Retryable handler error and `canRetry` is `false` | Commits the failure state with an `exhausted` receipt and throws the handler error. Redelivery of that event reports exhaustion without running the handler. |
| `UnretriableException` from the handler | Commits the failure state with an `unretriable` receipt and returns `{ status: 'final', state }`. |

A busy claim raises `ConflictException` (HTTP 409). A missing entity, invalid event ID, unknown event, or invalid transition raises `BadRequestException`. If guards rule out an otherwise matching transition in an idle state, the attempt returns `idle` instead. Validation, guard, storage, and post-commit errors propagate without requesting a retry.

Promise-based callers can subscribe and await the single result with `firstValueFrom`:

```typescript
import { firstValueFrom } from 'rxjs';

const result = await firstValueFrom(orchestrator.transit({
	event: 'order.submit',
	urn: orderId,
	eventId: commandId,
	attempt: 0,
}));
```

#### `getRetryConfig(event)`

Returns the retry configuration for a given event handler, if one was set via `@WithRetry`.

##### Signature

```typescript
getRetryConfig(event: string): IBackoffRetryConfig | undefined
```

##### Parameters

- `event`: The event name to look up retry config for

##### Returns

The `IBackoffRetryConfig` if the handler has `@WithRetry`, otherwise `undefined`.

The configuration describes the attempt limit and backoff. It does not change `transit()` behavior.

### Lifecycle

The service initializes routes on module initialization (`onModuleInit`):

1. Discovers all workflow classes
2. Extracts workflow definitions and handlers
3. Resolves entity services
4. Builds route map for event handling

## StateRouterHelperFactory

Factory for creating router helpers that assist with state routing logic.

### Import

```typescript
import { StateRouterHelperFactory } from 'nestflow-js/core';
```

### Methods

#### `create(event, entityService, workflowDefinition)`

Creates a new router helper instance.

##### Signature

```typescript
create<T, Event, State>(
	event: Event,
	entityService: IWorkflowEntity,
	workflowDefinition: IWorkflowDefinition<T, Event, State>,
): RouterService<T, Event, State>
```

## RouterService

Service responsible for routing workflow events to appropriate handlers.

### Note

This service is used internally by `OrchestratorService` and typically doesn't need to be used directly.
