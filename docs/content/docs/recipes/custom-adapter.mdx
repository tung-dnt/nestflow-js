---
title: Custom Adapter
description: Build your own adapter by extending BaseWorkflowAdapter to run workflows on any computing service.
---

Extend `BaseWorkflowAdapter` to drive workflows on a queue, an HTTP endpoint, or another runtime. Its loop calls `executeTransit` and dispatches each [TransitResult](/docs/api-reference/adapters#transitresult) to your adapter.

## Implement the adapter hooks

`BaseWorkflowAdapter<TContext, TResult>` takes an execution context and a result type. Expose an entry point that calls the protected `runWorkflowLoop(initialEvent, context)`.

| Method | When it runs | Return |
|--------|--------------|--------|
| `executeTransit` | Process the current event | `Promise<TransitResult>` |
| `onFinal` | The workflow returns a final state | `TResult` |
| `onIdle` | The workflow waits in an idle state | A promise for the next `IWorkflowEvent` |
| `onContinued` | The orchestrator finds an automatic transition | A promise for `result.nextEvent` |
| `onNoTransition` | The workflow needs an explicit event | A promise for the next `IWorkflowEvent` |

Require an `eventId` at your entry point. Use a producer's stable message ID or a caller-supplied idempotency key. Reuse it for retries and redeliveries of the same logical event. Never reuse it for another event on the same entity. Pass `result.nextEvent` through unchanged for automatic transitions.

## Retry only classified handler failures

Call `orchestrator.transit(event)` if you do not need retries. It runs one attempt, even for handlers decorated with `@WithRetry`.

To honor `@WithRetry`, implement `executeTransit` like this in a Node.js adapter:

```typescript
import { setTimeout as sleep } from 'node:timers/promises';
import { RetryBackoff } from 'nestflow-js/core';
import type { IWorkflowEvent, TransitResult } from 'nestflow-js/core';

// Method in your BaseWorkflowAdapter subclass.
protected async executeTransit(event: IWorkflowEvent): Promise<TransitResult> {
	const config = this.orchestrator.getRetryConfig(event.event);
	if (!config) return this.orchestrator.transit(event);

	let attempt = 0;
	for (; attempt + 1 < config.maxAttempts; attempt++) {
		const result = await this.orchestrator.transitAttempt({ ...event, attempt }, true);
		if (result.status !== 'retry') return result;
		await sleep(RetryBackoff.calculateDelay(attempt, config));
	}

	return this.orchestrator.transitAttempt({ ...event, attempt }, false);
}
```

The last attempt passes `false` so a handler failure commits the configured failed state and its exhaustion receipt before the error propagates. Do not catch and retry thrown errors. Validation, guard, claim, storage, and post-commit errors are not handler retry signals. For HTTP, preserve the `409 Conflict` response when another transition holds the entity's claim.

## Run without an adapter

Call `transit()` once per event. The loop below follows automatic transitions and returns as soon as the workflow finishes or needs input.

```typescript
import type { IWorkflowEvent, OrchestratorService, TransitResult } from 'nestflow-js/core';

async function runUntilPause(
	orchestrator: OrchestratorService,
	initialEvent: IWorkflowEvent,
): Promise<TransitResult> {
	let event = initialEvent;

	while (true) {
		const result = await orchestrator.transit(event);
		if (result.status !== 'continued') return result;
		event = result.nextEvent;
	}
}
```
