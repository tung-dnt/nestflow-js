Run a complete order workflow in one Node process. This example uses an in-memory entity store and does not need cloud credentials or a database.

## Installation

Use NestJS 12 with Node.js 22.12 or later. See the [NestJS 12 migration guide](https://docs.nestjs.com/migration-guide).

```bash
pnpm add nestflow-js @nestjs/common@12 @nestjs/core@12 reflect-metadata@^0.2.0 rxjs@^7.8.0
```

The TypeScript examples use ESM (`"type": "module"` in `package.json` and `"module": "NodeNext"` in `tsconfig.json`). Enable `experimentalDecorators` and `emitDecoratorMetadata` in `tsconfig.json`.

## 1. Define Your Entity

Create `order.ts`:

```typescript
export enum OrderStatus {
  Pending = 'pending',
  Processing = 'processing',
  Completed = 'completed',
  Failed = 'failed',
}

export interface Order {
	id: string;
	status: OrderStatus;
}
```

## 2. Create an Entity Service

Create `order-entity.service.ts`. The adapter owns claims and receipts. Your service chooses the initial state and ID.

```typescript
import { randomUUID } from 'node:crypto';
import { InMemoryWorkflowEntity } from 'nestflow-js/adapter';
import { defer, of, type Observable } from 'rxjs';
import { OrderStatus, type Order } from './order.js';

export class OrderEntityService extends InMemoryWorkflowEntity<Order, 'status'> {
	constructor() {
		super('status');
	}

	create(): Observable<Order> {
		return defer(() => of(this.save({ id: randomUUID(), status: OrderStatus.Pending })));
	}
}
```

This store loses all orders on restart. Do not share a workflow across processes using this store. For durable runs, supply a [storage-backed entity service](/docs/concepts/entity-service).

## 3. Define a Workflow

Create `order.workflow.ts`:

```typescript
import { Workflow, OnEvent, Entity } from 'nestflow-js/core';
import { OrderStatus, type Order } from './order.js';

@Workflow({
  name: 'OrderWorkflow',
  states: {
    finals: [OrderStatus.Completed, OrderStatus.Failed],
    idles: [OrderStatus.Pending],
    failed: OrderStatus.Failed,
  },
  transitions: [
    {
      event: 'order.submit',
      from: [OrderStatus.Pending],
      to: OrderStatus.Processing,
    },
    {
      event: 'order.complete',
      from: [OrderStatus.Processing],
      to: OrderStatus.Completed,
    },
  ],
  entityService: 'entity.order',
})
export class OrderWorkflow {
	@OnEvent('order.submit')
	async onSubmit(@Entity() order: Order) {
		return { orderId: order.id };
	}

	@OnEvent('order.complete')
	async onComplete(@Entity() order: Order) {
		return { orderId: order.id };
	}
}
```

## 4. Register the Module

Create `order.module.ts`. Register `OrderEntityService` under the token used in the workflow definition.

```typescript
import { Module } from '@nestjs/common';
import { WorkflowModule } from 'nestflow-js/core';
import { OrderEntityService } from './order-entity.service.js';
import { OrderWorkflow } from './order.workflow.js';

@Module({
  imports: [
    WorkflowModule.register({
      entities: [
        { provide: 'entity.order', useClass: OrderEntityService },
      ],
      workflows: [OrderWorkflow],
    }),
  ],
})
export class OrderModule {}
```

## 5. Submit an event

Create `submit-order.ts`. In an application, use the ID of the command that submits the order. Reuse it if you redeliver the command.

```typescript
import { NestFactory } from '@nestjs/core';
import { runInProcess } from 'nestflow-js/adapter';
import type { OrderEntityService } from './order-entity.service.js';
import { OrchestratorService } from 'nestflow-js/core';
import { firstValueFrom } from 'rxjs';
import { OrderModule } from './order.module.js';

const app = await NestFactory.createApplicationContext(OrderModule);
try {
	const orchestrator = app.get(OrchestratorService);
	const order = await firstValueFrom(app.get<OrderEntityService>('entity.order').create());
	const result = await firstValueFrom(runInProcess(orchestrator, {
		event: 'order.submit',
		urn: order.id,
		eventId: 'submit-command-456',
		attempt: 0,
	}));
	console.log(result);
} finally {
	await app.close();
}
```

Compile and run `submit-order.ts` with your NestJS project. The runner follows `order.complete` and prints `{ status: 'final', state: 'completed' }`.

If another transition holds the entity claim, the call raises `ConflictException` (HTTP 409). Requeue the same event with backoff instead of assigning a new ID. `transit()` itself does not retry.
