This guide registers an order workflow and submits its first event. To run the complete application with DynamoDB, use the [Lambda order state machine](https://github.com/tung-dnt/nestflow-js/tree/main/examples/lambda-order-state-machine).

## Installation

Use NestJS 12 with Node.js 22.12 or later. See the [NestJS 12 migration guide](https://docs.nestjs.com/migration-guide).

```bash
bun add nestflow-js @nestjs/common@12 @nestjs/core@12 reflect-metadata rxjs
```

## 1. Define Your Entity

```typescript
export enum OrderStatus {
  Pending = 'pending',
  Processing = 'processing',
  Completed = 'completed',
  Failed = 'failed',
}

export interface Order {
	id: string;
	status: OrderStatus;
}
```

## 2. Create an Entity Service

Use a storage-backed `IWorkflowEntity<Order, OrderStatus>` implementation. Its `claimTransition(urn, eventId)` method must acquire an exclusive claim or return the receipt for an event that already committed.

For a working implementation, see the [DynamoDB entity service](https://github.com/tung-dnt/nestflow-js/blob/main/examples/lambda-order-state-machine/src/order/order-entity.service.ts). See [entity service](/docs/concepts/entity-service) for the storage requirements.

## 3. Define a Workflow

```typescript
import { Workflow, OnEvent, Entity } from 'nestflow-js/core';

@Workflow({
  name: 'OrderWorkflow',
  states: {
    finals: [OrderStatus.Completed, OrderStatus.Failed],
    idles: [OrderStatus.Pending],
    failed: OrderStatus.Failed,
  },
  transitions: [
    {
      event: 'order.submit',
      from: [OrderStatus.Pending],
      to: OrderStatus.Processing,
    },
    {
      event: 'order.complete',
      from: [OrderStatus.Processing],
      to: OrderStatus.Completed,
    },
  ],
  entityService: 'entity.order',
})
export class OrderWorkflow {
	@OnEvent('order.submit')
	async onSubmit(@Entity() order: Order) {
		return { orderId: order.id };
	}

	@OnEvent('order.complete')
	async onComplete(@Entity() order: Order) {
		return { orderId: order.id };
	}
}
```

## 4. Register the Module

Register your storage-backed `OrderEntityService` under the token used in the workflow definition.

```typescript
import { Module } from '@nestjs/common';
import { WorkflowModule } from 'nestflow-js/core';

@Module({
  imports: [
    WorkflowModule.register({
      entities: [
        { provide: 'entity.order', useClass: OrderEntityService },
      ],
      workflows: [OrderWorkflow],
    }),
  ],
})
export class OrderModule {}
```

## 5. Submit an event

Create a pending order through your entity service. Pass its ID and the ID of the command that submits it. Preserve that command ID if you redeliver the event.

```typescript
import { Injectable } from '@nestjs/common';
import { OrchestratorService } from 'nestflow-js/core';

@Injectable()
export class OrderService {
	constructor(private readonly orchestrator: OrchestratorService) {}

	submitOrder(orderId: string, commandId: string) {
		return this.orchestrator.transit({
			event: 'order.submit',
			urn: orderId,
			eventId: commandId,
			attempt: 0,
		});
	}
}
```

The first call commits `Processing` and returns `continued` with an `order.complete` event. Pass `result.nextEvent` unchanged to `transit()` to finish the workflow. The next result is `final` with state `Completed`.

If another transition holds the entity claim, the call raises `ConflictException` (HTTP 409). Requeue the same event with backoff instead of assigning a new ID. `transit()` itself does not retry.
